# Нетехническое ТЗ: vv-db-connection

## 1. Назначение

`vv-db-connection` — библиотека, которая даст приложению единый способ работать с базами данных четырёх типов: **MSSQL, Oracle, PostgreSQL, Firebird**.

Приложение будет описывать подключение одним набором настроек и дальше обращаться к базе одинаково, независимо от производителя: «выполни запрос», «выдавай строки по мере поступления», «выполни несколько действий как одно целое», «проверь, жива ли база», «какая у неё версия». Все различия между СУБД — синтаксис параметров, способы отмены, подсчёт изменённых строк, поведение при обрыве связи — библиотека возьмёт на себя. Остальной код приложения не будет знать, с какой именно базой он работает.

Слой будет вынесен из существующего проекта (gi-bridge), где он уже работал, с сохранением поведения, и оформлен как самостоятельный публичный пакет. Лицензия — MIT.

## 2. Потребители

- **gi-bridge** — перенос и согласование данных между базами разных производителей (источник слоя).
- **vv-db-mcp** — сервер, дающий ИИ-агенту доступ к базам; весь доступ к СУБД пойдёт через эту библиотеку.
- Любое стороннее приложение, которому нужно работать с одной или несколькими из четырёх СУБД через один интерфейс.

Типичный сценарий: приложение одновременно держит открытыми «исходную» и «целевую» базы (возможно, разных производителей), читает из одной, пишет в другую.

## 3. Возможности

### 3.1. Подключение

- Подключение описывается простым набором настроек: тип базы, адрес, порт, база/сервис, учётные данные и несколько дополнительных опций, свойственных конкретной СУБД (шифрование, кодировка, размер пула и т.п.). Формат этих настроек принадлежит самой библиотеке.
- Для MSSQL будет два способа входа: логин SQL Server и доменная (Windows) аутентификация. Для Oracle — возможность входа с административными привилегиями.
- Подключений может быть сколько угодно и к разным СУБД одновременно; каждое независимо от других.
- Соединение будет открываться не при создании объекта, а при первом обращении; дальше соединения будут переиспользоваться (пул). По окончании работы приложение явно освобождает ресурсы.
- Если приложению нужна только одна СУБД, остальные три драйвера ему ставить не придётся — библиотека подгружает драйвер только той базы, которая реально используется.
- Можно ограничить время установки соединения, чтобы недоступный сервер не «подвешивал» приложение на минуты.
- Ошибки в настройках (отрицательный таймаут, неверный размер пула) будут считаться ошибкой программиста и обнаруживаться сразу при создании подключения, ещё до попыток связаться с базой.

### 3.2. Запрос с полным результатом

Приложение отправляет любой SQL-запрос и получает результат целиком:

- **чтение** — описание столбцов и строки;
- **изменение данных** — сколько строк база реально изменила;
- **изменение структуры** — подтверждение выполнения или ошибку.

Если запрос состоит из нескольких операторов и СУБД это допускает, результат придёт по каждому оператору отдельно. Для Oracle будут поддержаны процедурные блоки, возвращающие наборы данных, и выходные параметры.

### 3.3. Потоковый запрос

Для больших выборок приложение сможет получать строки по одной, по мере поступления, не накапливая всё в памяти. Поток всегда завершается ровно одним сигналом «конец» — с ошибкой или без, что бы ни случилось. Ошибка в обработчике самого приложения не обрушит процесс и не испортит драйвер: она будет превращена в ошибку завершения потока.

### 3.4. Единые параметры запросов

Значения передаются в запрос отдельно от текста, с одинаковым синтаксисом именованных параметров для всех четырёх СУБД. Библиотека сама переведёт их в «родной» вид каждой базы и не тронет похожие на параметры фрагменты внутри строк, имён в кавычках и комментариев. Если в запросе упомянут параметр, которого не передали, запрос будет отклонён понятной ошибкой ещё до отправки на сервер. Для MSSQL и Oracle можно будет явно указать тип параметра.

### 3.5. Транзакции

Приложение передаёт свой фрагмент кода, внутри которого выполняет несколько запросов. Если фрагмент отработал без ошибок — всё фиксируется, при любой ошибке — откатывается. Внутри транзакции можно прочитать только что изменённые данные до фиксации и вернуть наружу вычисленное значение (например, новый идентификатор).

Транзакцию можно ограничить по времени и отменить извне. Если истекло время именно на этапе фиксации, библиотека честно сообщит, что исход неизвестен (изменения могли уже сохраниться), — чтобы приложение не повторило операцию вслепую.

### 3.6. Защита от зависаний и отмена

- Запрос, который «замолчал» (нет первых данных или нет новых данных дольше заданного времени), будет прерван на любой СУБД, и приложение сразу получит управление обратно — даже если драйвер сам застрял.
- Любой запрос и любую транзакцию можно отменить извне; соединение при этом будет разорвано, а не оставлено висеть на сервере.
- Обрыв связи посреди работы завершает операцию ошибкой, а не бесконечным ожиданием.

### 3.7. Понятные ошибки

Ни один метод не будет «выбрасывать» сбои базы наружу исключениями — каждый вернёт единый ответ «успех + результат» или «неудача + ошибка». Ошибка скажет, **что** произошло: не удалось подключиться, упал запрос, не прошла фиксация транзакции, ошибся сам код приложения, истекло время, операция отменена. Это нужно для логики повторов: повторять имеет смысл взаимоблокировку, но не ошибку в собственном коде. Исключения будут только для ошибок программиста (неверные значения таймаутов).

### 3.8. Служебные действия

- **Проверка доступности** — минимальный запрос, не требующий прав; удобен для ожидания запуска базы.
- **Версия сервера** — строка версии; для Oracle — с запасным способом для пользователя без особых прав.
- **Описание подключения** для логов: тип базы, «адрес [база]» и имя пользователя — без открытия соединения.

## 4. Сценарии использования

1. **Перенос данных между базами.** Приложение открывает MSSQL-источник и PostgreSQL-приёмник, потоково читает большую таблицу из первой и пачками пишет во вторую в транзакциях.
2. **Ожидание старта базы.** Скрипт развёртывания в цикле вызывает проверку доступности с коротким таймаутом, пока база не ответит.
3. **Операция «всё или ничего».** Вставка заголовка и строк документа в одной транзакции с возвратом нового идентификатора; при сбое — откат и решение о повторе по виду ошибки.
4. **Долгий отчёт с отменой.** Пользователь закрыл экран — приложение отменяет запрос, соединение освобождается, сервер прекращает работу.
5. **Тесты приложения.** Низкоуровневый контракт подключения доступен, чтобы подменять базу в тестах.

## 5. Чего в библиотеке не будет

- Собственного логирования и метрик.
- ORM, построителя запросов, миграций, чтения структуры базы (каталога).
- Хранения или шифрования учётных данных — их передаёт приложение.
- Поддержки других СУБД, кроме четырёх названных.

## 6. Известные ограничения (осознанно)

- Шифрование соединений по умолчанию будет нестрогим ради совместимости; строгую проверку сертификата приложение включает явно.
- Firebird будет открывать новое соединение на каждый запрос (у драйвера нет пула), двоичные BLOB-поля не поддерживаются.
- Для MSSQL/Firebird при изменении с возвратом строк возвращаются строки, а число изменённых строк может не прийти.
- Часть защитных механизмов опирается на внутреннее устройство драйверов; при их обновлении поведение нужно перепроверять.
